# s.tw14.ru — paste service

Один файл на stdlib Python, слушает `127.0.0.1:8091`, наружу — nginx с TLS.
База: `data/paste.db` (SQLite, WAL). Файлы хранятся BLOB'ами в таблице `files`.

## Эндпоинты

- `GET /` — форма.
- `POST /api/share` — создать пасту.
  - JSON: `{"text": "...", "ttl": "1d", "burn": false}`.
  - `multipart/form-data`: поля `text`, `ttl`, `burn`, один или несколько `files`.
    Текст можно оставить пустым, если есть файлы.
  - Ответ: `{id, url, expires_at, expires_human, delete_url, files}`.
- `GET /<id>` — страница пасты со списком файлов.
- `GET /<id>/raw` — текст как `text/plain` (`?download=1` — скачивание).
- `GET /<id>/f/<n>` — скачивание вложения.
- `GET /d/<token>` — удалить пасту и её файлы (одноразовая ссылка).
- `GET /healthz` — `ok`.

## Форма

Файлы можно выбрать кнопкой, перетащить в окно или вставить скриншот из буфера
обмена через `Ctrl+V`. Вставленные изображения получают имя вида
`screenshot-YYYYMMDD-HHMMSS.png`.

## Лимиты

- Текст: 1 МБ.
- Один файл: 10 МБ; до 5 файлов; суммарно до 20 МБ на пасту.
- Весь multipart-запрос: 25 МБ (в nginx `client_max_body_size 26m`).
- Не больше 200 МБ загрузок с одного IP в час.
- Общий объём вложений в базе: 20 ГБ.
- TTL: от 60 секунд до 30 дней; по умолчанию 1 день.
- Запись: 30 запросов/мин с IP, чтение: 240/мин.

## Burn

Без файлов паста удаляется при первом просмотре. Если есть файлы, текст
удаляется сразу, а вложения остаются доступны 10 минут, чтобы получатель
успел их скачать; затем строка удаляется janitor'ом.

## Обслуживание

```bash
systemctl --user restart paste.service
journalctl --user -u paste.service -n 50
```

Схема `files` создаётся автоматически при старте (`init_db`). Удаление пасты
каскадно удаляет файлы (`PRAGMA foreign_keys=ON`).
